## High

1. **The registry lock does not serialize a seat’s lifecycle.** `spawn` checks and opens its window before locking; `retire` kills its window before locking; refresh locks only its registry rewrite ([team.sh:1120](../../../tools/team.sh), [team.sh:1123](../../../tools/team.sh), [team.sh:1277](../../../tools/team.sh), [team.sh:610](../../../tools/team.sh)). If retirement removes a record first, refresh’s `awk` can succeed while updating zero rows. If a seat name is reused before step 6, refresh can select and respawn the replacement pane ([team.sh:611](../../../tools/team.sh), [team.sh:622](../../../tools/team.sh)). **Impact: high** for the operator and seat: a newly started session can be stopped by an older refresh, or the registry can cease to describe the running seat. This is **drift from code round 1, finding 2**. Take the registry lock before the lifecycle checks and window mutation, and verify that the expected record and pane still belong to the refresh before restart.

2. **An idle screen does not establish that the handoff file is complete.** Step 2 notices an existing file and one idle pane snapshot; step 3 reads its first line, then step 6 restarts the pane ([team.sh:567](../../../tools/team.sh), [team.sh:578](../../../tools/team.sh), [team.sh:634](../../../tools/team.sh)). A writer can create the file before finishing it. A partial first line causes a false rejection; a complete first line with an unfinished body can be handed to the new session while the old one is stopped. **Impact: high** for the seat and operator: handoff work can be lost. This is **drift from code round 1, finding 1**, which raised the same file-completion gap. Require a completion signal tied to the outgoing session before restart.

## Medium

3. **Failed state reads still become absence, delay, or the wrong outcome.** These are the remaining instances in the scoped diff:

   - Step 0’s `record` failure is reported as “not recorded,” even though `awk` can fail after the readability check ([team.sh:1238](../../../tools/team.sh), [team.sh:1244](../../../tools/team.sh)).
   - Step 2 treats a failed handoff-file test, a `queued_for` failure, or a failed `seat_pane` read as another wait and eventually reports “no handoff” ([team.sh:567](../../../tools/team.sh), [team.sh:569](../../../tools/team.sh), [team.sh:570](../../../tools/team.sh)).
   - `queued_for` can return `no` when a path component or listing could not be established as readable; the ancestor search only checks `-e` and `-x` ([team.sh:435](../../../tools/team.sh), [team.sh:443](../../../tools/team.sh)).
   - `pane_state` reports `busy` on visible “Working” text before proving there is a pi input box. A non-pi pane can therefore be deferred until timeout instead of reported unreadable ([team.sh:424](../../../tools/team.sh), [team.sh:427](../../../tools/team.sh)).

   **Impact: medium** for the operator: the stated failure cause is hidden, and a queued message can be mistaken for no queue. This conflicts with the `full` tier’s three-way read rule ([rules.md:15](../../../docs/rules.md)) and the ticket’s step 0, 1 and 2 outcomes ([01-refresh.md:40](../issues/01-refresh.md), [01-refresh.md:43](../issues/01-refresh.md), [01-refresh.md:45](../issues/01-refresh.md)). It is **drift from code round 1, findings 3 and 5**.

4. **Some failure paths leave locks or records in a misleading state.** If `spawn` cannot append its record, `set -e` exits after opening the window, leaving both the unrecorded live window and `$agents.lock` ([team.sh:1123](../../../tools/team.sh), [team.sh:1125](../../../tools/team.sh)). If `refresh_lock` creates its directory but cannot write `since`, the current seat’s lock is left behind because it is not yet in `taken` ([team.sh:455](../../../tools/team.sh), [team.sh:468](../../../tools/team.sh), [team.sh:1248](../../../tools/team.sh)). A failed `retire` rewrite leaves `$agents.new` after the window has closed ([team.sh:1278](../../../tools/team.sh), [team.sh:1281](../../../tools/team.sh)). **Impact: medium** for the operator: subsequent operations can be refused as running, or a seat can run without a registry record. These are **drift from code round 1, finding 2**.

5. **The new EXIT cleanup does not check lock ownership.** `refresh_exit` removes the named seat lock regardless of whether this `_refresh` invocation acquired it ([team.sh:518](../../../tools/team.sh), [team.sh:523](../../../tools/team.sh)). `_refresh` is callable without the foreground lock path; the new selftest deliberately does so ([team.sh:873](../../../tools/team.sh)). A stray invocation for a seat already refreshing can overwrite its lock PID and remove that run’s lock on exit, permitting another refresh. **Impact: medium** for the seat: overlapping runs can restart the same pane. This is **drift from code round 1, finding 4’s EXIT-trap fix**. Make cleanup conditional on ownership. This is separate from the recorded stale-lock takeover race.

6. **A failed ledger-path lookup can silently omit start and stop lines.** `tmux()` returns the same `undefined` for a failed command and an unset `@team-ledger`; `write()` then returns without warning ([ledger.ts:38](../../../tools/extensions/ledger.ts), [ledger.ts:58](../../../tools/extensions/ledger.ts)). The response calls that a choice for panes outside a team server ([response.md:27](review-codex-202611180738-f49e4ed-response.md)); it does not distinguish a failed read inside one. **Impact: medium** for the operator: a team session can start or stop without its required ledger event or notification. This is **drift from code round 1, finding 6’s class sweep**. Preserve the silent outcome for a genuinely unset option and surface a failed lookup.

## Low

7. **Two revised selftest checks can still pass on broken behavior.** `reported_once` is evaluated after a fixed three-second sleep, so a later duplicate report passes; `all_requested` compares aggregate counts, so two requests for one seat and none for another can pass ([team.sh:809](../../../tools/team.sh), [team.sh:816](../../../tools/team.sh), [team.sh:905](../../../tools/team.sh)). **Impact: low** for maintainers: regressions can retain a green selftest. This is **drift from code round 1, finding 8**. Assert the report count after the run’s lock is released and count requested events by seat. **Delete the three-second sleep**: it is a timing-only check added where a completion signal already exists ([team.sh:906](../../../tools/team.sh), [team.sh:908](../../../tools/team.sh)).
