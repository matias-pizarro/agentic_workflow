# 1a. /refresh code review (code round 1)

Reviewed `git diff integration...f49e4ed` against the ticket, perimeter and rules. **There are findings above low severity.** All findings are in ticket changes; this is round 1, so none is drift from an earlier review round. This was a read-only review; I did not edit files or run the live check.

## High

1. **A refresh can stop the old session while its input box holds text.** After the handoff file appears, step 2 accepts `typing` as completion and proceeds to `respawn-pane -k` ([team.sh:514](../../../tools/team.sh), [team.sh:574](../../../tools/team.sh)). The ticket requires the pane to be idle again ([01-refresh.md:42](../issues/01-refresh.md)); the perimeter says the old session stays untouched until restart ([perimeter.md:29](../perimeter.md)). A file can also be observed before its writer finishes, so this path can reject a partial first line or restart before the handoff is complete. **Impact: high** for the seat and operator: half-typed input or unfinished handoff work can be lost. Require an idle, completed handoff before step 3.

2. **The registry and refresh locks do not protect concurrent seat changes.** Refresh locks its registry rewrite, but `spawn` appends and `retire` rewrites without that lock ([team.sh:549](../../../tools/team.sh), [team.sh:1031](../../../tools/team.sh), [team.sh:1180](../../../tools/team.sh)). A refresh can overwrite a newly spawned seat or continue after a seat is retired. Two lock ownership races also permit overlapping refreshes: dead-PID recovery removes a lock another caller may just have replaced, and a multi-seat foreground refusal removes locks already handed to background runs ([team.sh:429](../../../tools/team.sh), [team.sh:1152](../../../tools/team.sh)). **Impact: high** for affected seats: records can disappear or two runs can restart one pane. Use one registry lock across mutations and preserve ownership when handing off or recovering refresh locks.

## Medium

3. **Failed state reads are treated as absence or substituted state.** Step 0 treats failed registry and tmux reads as “not recorded” or “no window” ([team.sh:303](../../../tools/team.sh), [team.sh:397](../../../tools/team.sh), [team.sh:1144](../../../tools/team.sh)). `session_of` turns failed pane-option reads into a registry ID or blank metadata ([team.sh:447](../../../tools/team.sh)). Queue existence or enumeration failures can return `no`, and failed handoff-file checks are treated as “not yet present” ([team.sh:417](../../../tools/team.sh), [team.sh:509](../../../tools/team.sh), [team.sh:514](../../../tools/team.sh)). These are instances of the same violation of the `full` tier’s three-way read rule ([rules.md:15](../../../docs/rules.md)). **Impact: medium** for the operator: a refresh may proceed with a queued message, misidentify the session, or report an absence or timeout instead of the read failure.

4. **Several failures bypass the promised outcome report.** With `set -e`, failures while writing the background PID, resolving paths, generating the new ID, or composing the first prompt can exit `refresh_run` without `refresh_end` ([team.sh:61](../../../tools/team.sh), [team.sh:476](../../../tools/team.sh), [team.sh:479](../../../tools/team.sh), [team.sh:533](../../../tools/team.sh), [team.sh:571](../../../tools/team.sh)). `uuidgen | tr` can additionally yield an empty ID because the pipeline reports `tr`’s status. If `enqueue lead` fails, the final report is lost ([team.sh:464](../../../tools/team.sh)). The handoff-directory failure has an implemented outcome but no row in the failure table ([team.sh:507](../../../tools/team.sh), [01-refresh.md:38](../issues/01-refresh.md)). **Impact: medium** for the operator: a run can end silently or start a session with an invalid ID, contrary to the one-report criterion ([01-refresh.md:35](../issues/01-refresh.md)).

5. **The post-respawn check can report success without verifying the new pi.** It succeeds for any state other than `unreadable`; `busy` is determined by visible “Working” text without first proving an input box exists, and no session ID is checked ([team.sh:405](../../../tools/team.sh), [team.sh:577](../../../tools/team.sh)). **Impact: medium** for the operator: a readable shell or wrong pane contents can be reported as the new seat, concealing a failed restart. Verify the new input box and session identity.

6. **Ledger metadata failures are silent or recorded as valid data.** A failed window-name read writes a start or stop with an empty seat, while failed updates of `@session-id` and `@session-name` are ignored ([ledger.ts:42](../../../tools/extensions/ledger.ts), [ledger.ts:49](../../../tools/extensions/ledger.ts)). **Impact: medium** for the operator: the ledger and later refresh reports can carry a blank or stale seat, ID or name. Normal `/new`, resume, fork, `/reload`, and graceful shutdown wiring showed no demonstrated missed or doubled event; outside team tmux it writes nothing.

7. **Step 0 hides tmux’s start error.** The failure table promises refusal with tmux’s error ([01-refresh.md:43](../issues/01-refresh.md)), but `run-shell` stderr is discarded and replaced with “server cannot be reached” for every failure ([team.sh:1163](../../../tools/team.sh)). **Impact: medium** for the operator: a real start failure is misdiagnosed, delaying recovery.

## Low

8. **Several selftest assertions can pass on stale evidence or timing.** The “one report” check only tests existence, so duplicates pass; the second unadvisable run checks the previous run’s reason and report ([team.sh:743](../../../tools/team.sh), [team.sh:821](../../../tools/team.sh), [team.sh:827](../../../tools/team.sh)). Several transition waits discard failure with `|| true`, and the `all` count comparison is expanded before `waitfor` polls it ([team.sh:799](../../../tools/team.sh), [team.sh:848](../../../tools/team.sh), [team.sh:853](../../../tools/team.sh)). The stub produces no pi lifecycle events, while the pure test checks only the reason predicate ([team.sh:766](../../../tools/team.sh), [run.mjs:43](../..//../tests/refresh/run.mjs)). **Impact: low** for maintainers: broken outcomes can retain a green selftest. Compare per-run counts and outcomes, and make required transition waits fail the test.

9. **Delete the unused `refreshes` selftest helper.** It has no caller ([team.sh:756](../../../tools/team.sh)). **Impact: low** for maintainers: it adds an unnecessary testing surface. Deleting it satisfies the over-build check in [rules.md:34](../../../docs/rules.md).
