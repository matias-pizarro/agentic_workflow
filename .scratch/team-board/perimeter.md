# Team board: perimeter

Ceremony: script (the user, "yes", team-board pane 20 Nov 2026 20:33, to TB-Q17: `implement`, this file as the brief, in three pieces: (1) the shared changes, `open-questions.ts` publishing the seat's fields and reading `for=`, `team.sh spawn` writing a ledger line, merged on their own first, the rules.md wording handed to agentic-workflow; (2) `tools/board.mjs` iteration 1; (3) iteration 2).

**If it fails:** the board shows a stale or wrong row, or exits; the seats, the ledger and Vikunja are untouched, since it only reads them and its actions are `team.sh` commands the operator confirms.

The user's request (20 Nov 2026 11:38 CET), via the lead's brief: a script drawing a table of all seats in pane 0, redrawn on each new message; a second iteration as an ncurses table like top, filterable and sortable, with actions; the same for tasks.

## Decisions

- **TB-Q1** Seats' fields come from tmux window options that `open-questions.ts` publishes at each turn's end (`@state`, `@worst`, `@ctx`, `@ask`, beside the existing `@open`, `@working`, `@todo`, `@wait`); a seat that has not reloaded the extension yet is read by scraping its pane's last STATUS line, as `team.sh status` does (the user, "yes", team-board pane 20 Nov 2026 11:43).
- **TB-Q2** The waited-for party is a new STATUS field, which changes rules.md's Team mechanics; the rules.md edit is agentic-workflow's, handed through the lead, and merges on its own (the user, "b", to the option naming the rules.md change, team-board pane 20 Nov 2026 11:47).
- **TB-Q3** The field is `for=<PM|lead|seat-name>`, placed right after `state=`: `STATUS seat=… state=… [for=…] open=… [worst=…] [ask=…] [pointer=…]`; required for `waiting-for-PM` (PM), `ready-for-lead` (lead) and `waiting-for-seat` (the first seat waited for), left out otherwise; a line without it is derived from its state and the first seat named in `ask=` (the user, "placed after `state`", team-board pane 20 Nov 2026 11:48). `open-questions.ts`'s STATUS match must then allow `for=` between `state=` and `open=`.
- **TB-Q4** The icon column shows the seat's tab icon, from the same window options: ⚡ working, ✋ waits on PM, ⏳ waits on the team, otherwise empty (the user, "yes", team-board pane 20 Nov 2026 11:50).
- **TB-Q5** "Since refresh" is the time since the first ledger `start` line of the seat's current session id (`tools/agents`); "since creation" the time since a new `spawn` ledger line that `team.sh spawn` writes, else the seat's earliest ledger line, else `?`. Both shown as `Nd Nh Nm`, the `Nd` part only when N > 0 (the user, "yes, but Nd shown only if N>0", team-board pane 20 Nov 2026 11:52).
- **TB-Q6** Window 0 ("pane 0") is split side by side: the seats table on the left, the tasks table on the right (the user, "pane 0 would be divided vertically, with the agent list on the left and the task list on the right", team-board pane 20 Nov 2026 11:59). The board polls every 2 s (one `tmux list-windows` read, a stat of the ledger and `tools/agents`) and redraws when anything changed, and once a minute for the times (the user, "TB-Q6: a", same message).
- **TB-Q7** A seat is involved in a task when the task carries the label `seat:<name>`, or, failing that, when its title ends in `(<name>)` (the user, "yes", team-board pane 20 Nov 2026 12:10).
- **TB-Q8** A seat's state maps to a task status: `idle`, `done` → idle; `working` → working; `waiting-for-seat`, `ready-for-lead` → waiting for seat; `blocked` → blocked; `waiting-for-PM` → waiting for PM (the user, "idle, done -> idle / working -> working / waiting-for-seat, ready-for-lead -> waiting for seat / blocked -> blockeds / waiting-for-PM -> waiting for PM", team-board pane 20 Nov 2026 12:14; "blockeds" read as "blocked"). The order among them and the open sum: TB-Q9.
- **TB-Q9** A task's status is the worst among its seats', in the order idle < working < waiting for seat < blocked < waiting for PM; a task with no live seat shows `pending seat`; its open is the plain sum of its seats' `open=`, a seat on two tasks counting in both (the user, "A task with no live seat shows `pending seat` / yes to the rest", team-board pane 20 Nov 2026 12:27).
- **TB-Q10** The tasks table lists the undone tasks with a live seat, plus the undone tasks outside Backlog; worst status first, then by `#` (the user, "b", team-board pane 20 Nov 2026 12:33).
- **TB-Q11** The board reads tasks by GET on Vikunja's REST API with `curl`, the token passed on stdin from `VIKUNJA_TOKEN_FILE` (the sandbox bot's by default) as `src/scripts/vikunja-attach` does, with `VIKUNJA_URL` and the project id from its environment, every 60 s; a failed read keeps the last table and shows `tasks: read failed HH:MM <error>` above it (the user, "yes", team-board pane 20 Nov 2026 12:58). `src/docs/agents/issue-tracker.md`'s "the one place an agent uses the REST API" then needs a one-line edit by src's owner.
- **TB-Q13** The board is one dependency-free Node script, `tools/board.mjs` in the skills repo (the playbook), drawing a top-like full-screen table itself (no ncurses library); its tasks pane reads Vikunja only when `VIKUNJA_URL` is set (the user, "use ncurses", 13:08, then, after the trade-offs, "let's try b for now", team-board pane 20 Nov 2026 19:42). A choice for now: the C ncurses program with a sh collector stays the alternative.
- **TB-Q14** Iteration 2's actions: on a selected seat, `r` refresh and `R` retire run `team.sh refresh <seat> "board: r <seat>" "board pane HH:MM"` and `team.sh retire <seat>` themselves, after a typed `y`; window 0 is the operator's, so the key is their go there; retire never passes `--no-checkout`, and a refusal shows in the board's status line (the user, "yes", team-board pane 20 Nov 2026 19:48).
- **TB-Q15** The perimeter (the user, "TB-Q15: yes, but why can't the lead be a row?", team-board pane 20 Nov 2026 20:17; the lead row settled by TB-Q16):
  - In, iteration 1, read-only and redrawn: the seats table (name, icon, context %, state, open, waiting-for, since creation, since refresh); the tasks table (#, id, name, tier, link, seats, status, open, blocked-by); `board` splitting window 0 and starting both; the extension publishing `@state`, `@for`, `@worst`, `@ctx`, `@ask`; `team.sh spawn` writing a ledger line; `for=` in rules.md and the extension (agentic-workflow's).
  - In, iteration 2: both tables sortable by any column (`<` `>` move the sort column, `s` reverses) and filterable by text (`/`); arrows select a row; on seats, `r` refresh and `R` retire (TB-Q14).
  - Out: writes to Vikunja; task actions (the link column shows the URL); `spawn`, `send` or `--no-checkout` from the board; per-seat emoji; history or graphs. Outside the board's code: the `seat:<name>` labels (the operator creates them, seats attach them) and `issue-tracker.md`'s one-line edit (src's).
- **TB-Q16** The lead is a row of the seats table, sorted with the others, not pinned; read like any seat, its session id from its pane's `@session-id` and its pane found by `@role=lead`; `r` runs `team.sh refresh lead …`; `R` does nothing on it (the user, "TB-Q16: yes,. but do not pin the lead", team-board pane 20 Nov 2026 20:19).
